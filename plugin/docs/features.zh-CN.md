# 功能介绍

[English](en/features.md) · [README](../README.md) · [异常与恢复](boundaries.zh-CN.md)

## 从回复到下一条消息

插件预测的是**用户接下来可能发送给助手的一条消息**。它不会代替助手回答，也不会执行建议中的操作。

1. 用户发送消息，本线程进入新一轮。
2. 助手正常结束后，检查线程开关、黑名单、上下文映射、价格和未结算请求。
3. 同一来源已有结果就直接读取；已有生成任务就复用任务，否则发起预测。
4. 合格建议显示在空输入框中，随输入区域换行。按 **Tab** 填入可编辑草稿；是否发送由用户决定。

助手报错、取消、中断或仍在生成时，不自动预测。输入框已有内容、附件，或正处于输入法组合、菜单、排队发送等状态时，不用建议覆盖用户输入。切换线程后，只显示属于目标线程且来源仍有效的结果。

预测本身不进入真实对话历史，也不建立一个可见子线程。只有用户实际发送的消息才成为下一轮的真实输入。

## 哪些线程会生成

| 项目 | 默认与规则 |
| --- | --- |
| 新建线程 | 默认启用，可在设置中调整 |
| 单个线程 | 可单独开启、关闭或加入黑名单 |
| 工作区 | 可整体加入黑名单，优先于默认启用与补生成 |
| 已有线程补生成 | 默认取最近 24 小时内用户发送过消息的最新 3 个线程，可关闭或调整 |
| 已保存预测 | 没有按时间计算的过期时间；重新显示和接受前仍检查来源 |
| 用户继续发送 | 退出旧建议，等本轮助手正常结束后处理新预测 |

24 小时只用于已有线程的补生成筛选，活跃时间取**用户发送时间**。它不是建议寿命。一个月后打开线程，也可以复用仍符合当前来源的旧建议。

逻辑 watchdog 根据发送、正常结束、轮次与 token 增量、结构事件检查映射，不按秒重复扫描聊天。它与额度恢复检查是两套逻辑。

## 上下文与两层缓存

**本地结果缓存**保存生成过的建议。切换窗口、重复观察界面不会因此再买一次相同来源的预测。来源身份包括线程、轮次、上下文修订及有关配置；显示和接受时再次校验，迟到响应不会贴到其他轮次。

**服务商前缀缓存**由服务商决定，插件只能组织请求以便复用。尽量保留父请求中可复用的有效前缀，把变化较多的预测指令放在后部。模型、思考配置、工具定义或前部历史变化，都可能影响命中。

上下文选择比较完整有效上下文、前缀加尾部、局部窗口与冻结窗口等方案。主线程已经压缩时，继承其有效快照；不会偷偷恢复压缩前的全量历史。工具调用与结果按完整单元保留。当前版本**没有另外付费调用模型生成历史摘要的任务**。

外部插件改写历史后，旧来源先失效再重新映射。若预计保留的可复用前缀低于 **50%**，暂停该线程的被动预测。这里是本地前缀保留估计，不等于服务商 usage 中的实际缓存命中率。

窗口和修复选择器使用已知 token、价表和近期缓存证据估算成本。它不保证全局最优，也不保证某个命中率；长但高命中的输入可能比短的冷输入更便宜。

## 后端与思考配置

支持 DeepSeek、OpenAI Responses、Anthropic Messages 和 OpenAI Chat Completions。可沿用父请求配置，也可通过后端配置文件指定端点、模型、凭据引用、能力和价表。

默认思考策略为 **关闭 / 最低**：

- 已知模型支持关闭时，使用相应的关闭参数。
- 不能关闭时，使用该模型允许的最低档；最低档仍可能产生推理费用。
- 需要更高档时，在设置中选择“使用后端配置”并保存。修复请求遵循同一策略。
- 第三方别名不能只靠名字推断能力，需按配置声明。不会发付费请求试探能力，也不自动切换协议重发。

更换配置不会自动为当前轮再生成一次；需要时使用主动重试。关闭思考可能改变父请求的缓存兼容性，因此以实际 usage 为准。具体字段见 [协议配置](../PROTOCOL-COMPAT.zh-CN.md)。

## 提示词与本地限制

提示词要求一条用户视角的消息，使用用户语言，不能把助手的提议当作用户授权，不能凭空补任务、事实或价格。依据不足时返回 `suggestion:false`，本次不显示内容。

可编辑插件数据目录中的 `instruction_prediction.md` 添加个人约束。它的优先级低于强制规则，不能放宽长度、语言和可靠性检查。

| 设置 | 默认 |
| --- | --- |
| 建议长度偏好 | 普通，目标约 160 个可见文本 tokens |
| 可见建议硬上限 | 999，可调整 |
| 预测语言 | 自动分析用户语言，开启语言检查 |
| 截断 | 关闭 |
| 自动重试 | 开启 |
| 网络重试 | 最多额外 3 次 |
| 校验修复 | 最多额外 1 次 |
| 修复策略 | 自动比较仅修复草稿、父上下文重生、父上下文加草稿的预计费用 |

长度上限针对可见建议，不含 JSON 外壳和隐藏推理。已支持的模型使用对应计数器；未知模型使用保守的 UTF-8 字节上界，不把它宣称为精确 tokens。

本地还检查无可见内容、控制字符、内部推理或工具标记、解释性标签、明显助手视角、直接照抄助手、没有依据的数字价格及语言/字形不一致。语言或意图检测都有能力边界，用户应在发送前审阅草稿。

超长时可选择截断；截断后的内容仍需通过其他限制。未开启截断时，修复提示给出原长度、目标长度和应减少的绝对量/比例。默认自动选择成本方案，不能把“修复”理解为每次都重发全部历史。

## 费用与占比

费用页位于线程上方横向菜单的插件页面，不在输入框底部展开大段统计。

**Prediction 占比 = Prediction /（主会话 + Prediction）**，按线程、币种和覆盖范围分别计算。自动生成、主动重试、网络重试和校验修复的每次实际请求都单独入账。

请求开始时保存当时的价表与适用时段。峰谷价只按配置的生效区间和时区计算，不假设所有端点都有半价。缓存读取、缓存写入与普通输入按协议口径归一，避免重复计入；推理输出也不重复收费。

价格未知时在预测发送前拦截。请求发出后缺少最终 usage，则保留未结算状态并停止后续自动消费，不把未知费用当成零。历史记录不完整与安装后完整覆盖分开；占比中的“—”应结合覆盖提示解释，不能用已知小计冒充完整占比。详见 [统计排查](boundaries.zh-CN.md#费用与占比排查)。

## 数据与更新

设置、配置、黑名单、结果与账本保存在 `~/.dsh/plugins-data/composer-prediction`。选择的上下文会发送给所配置的模型服务商。审计快照和诊断可能含聊天内容，不应把整个数据目录发到公开 issue。

npm 来源安装使用 DSH 原生版本检查，在详情页查看版本、重新检查和选择更新。离线文件来源没有相同的 registry 更新来源。Windows 安装、校验和及离线步骤见 [安装说明](windows.zh-CN.md)。

故障时先看线程的“当前状态与特殊事件”，再对照 [异常与恢复](boundaries.zh-CN.md)。不要先删账本或反复点击重试。
